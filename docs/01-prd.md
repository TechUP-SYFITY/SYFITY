## 1. 제품 개요와 비전

### 1.1 제품 정의

Syfity는 여러 사용자가 하나의 Room에서 같은 음악을 실시간으로 감상하고, 공동 Playlist와 채팅으로 함께 소통하는 웹 기반 소셜 리스닝 플랫폼이다.

### 1.2 비전

음악을 단순히 동시에 재생하는 것을 넘어, 친구와 커뮤니티가 하나의 감상 공간을 만들고 다시 찾아오는 경험을 제공한다.

### 1.3 핵심 가치

- **빠른 참여**: Room 생성과 초대 코드·링크 기반 입장을 간단하게 제공한다.
- **함께 만드는 감상**: 참여자가 곡을 더하고 감상을 나누는 공동 Playlist 경험을 제공한다.
- **자연스러운 동기화**: 서버 기준 재생 상태와 자동 보정으로 같은 감상 흐름을 유지한다.
- **지속 가능한 Room**: Room 종료·복구, 개인 Playlist, 재방문 흐름을 통해 일회성 링크 공유를 넘어선다.

Syfity는 공동 감상, 공동 Playlist, 실시간 채팅을 하나의 Room 경험으로 제공한다. 경쟁 서비스 비교와 시장 근거는 시장 조사 문서에서 관리한다.

## 2. 사용자·문제 정의

### 2.1 사용자

| 사용자                           | 상황과 목표                                                    |
| -------------------------------- | -------------------------------------------------------------- |
| 친구와 함께 음악을 듣는 사용자   | 별도 설치 없이 Room에 들어가 같은 시점에 음악을 듣고 대화한다. |
| 음악 링크를 자주 공유하는 사용자 | 흩어진 링크 대신 함께 들을 곡을 한곳에 모아 관리한다.          |
| 온라인 모임·스터디·팬 커뮤니티   | 대화나 활동 중 공통 배경음악과 가벼운 감상 공간을 만든다.      |

### 2.2 해결하려는 문제

- 각자 재생을 시작하면 재생 시점이 쉽게 어긋난다.
- 음악 링크와 곡 추천이 여러 대화 채널에 흩어져 관리하기 어렵다.
- 음악을 들으며 대화하려면 별도 메신저나 음성 채널을 함께 사용해야 한다.
- 일회성 링크 공유만으로는 같은 사람들과 다시 감상할 Room 맥락을 남기기 어렵다.

### 2.3 사용자 목표

- **Host**: 감상 공간을 빠르게 만들고 재생 흐름과 참여자를 관리한다.
- **Member**: 초대받은 Room에 쉽게 입장하고 같은 감상 흐름에 참여한다.
- **모든 참여자**: 곡을 함께 쌓고 음악을 들으며 대화한다.

## 3. 제품 원칙과 서비스 제약

### 3.1 제품 원칙

1. **빠르게 함께 시작한다.** Room 생성·초대·입장은 복잡한 설정 없이 이어져야 한다.
2. **Room은 공동 감상 공간이다.** Playlist와 채팅은 Room 참여자가 함께 만드는 자산이다.
3. **동기화는 서버가 책임진다.** 재생 상태와 순서는 서버를 기준으로 관리하고 자동 보정한다.
4. **Host는 감상 흐름을 관리한다.** Host가 재생·순서·Room 운영을 책임지고, Member는 감상·곡 추가·채팅에 참여한다.
5. **참여를 방해하지 않는 소셜 경험을 만든다.** 채팅, 이모지, 개인 Playlist 같은 기능은 감상을 보완해야 한다.

### 3.2 서비스 제약

- YouTube 공식 IFrame Player와 정책을 준수한다.
- 자체 음원 스트리밍, MP3 추출·다운로드, 숨김 재생, 광고·버퍼링 우회는 제공하지 않는다.
- 실시간 감상·채팅·Room 입장은 네트워크 연결이 필요하다.
- Room은 로그인한 사용자 중심의 Private Room으로 운영한다.
- Host 위임과 자동 Host 승계는 지원하지 않는다.
- PWA는 설치와 기본 오프라인 안내를 제공하지만, 오프라인 음악 재생이나 Room 활동을 제공하지 않는다.

## 4. Room·역할·권한 모델

### 4.1 Room 모델

- Room은 기본적으로 Private이며 초대 코드·링크로 입장한다.
- Room 데이터는 물리 삭제하지 않고 상태로 관리한다.
- Home에는 참여 이력 기반의 최근 Room 목록과, Host 전용 `내 Room` 목록을 구분해 제공한다.

```text
active ── Host 명시적 Close / Host 재접속 타임아웃 ──→ closed
closed ── Host 복구 ──→ active
closed ── Host 명시적 비활성화 / closed 후 30일 경과 ──→ inactive
inactive ──→ 복구 불가
```

| 상태     | 입장 | Host 동작               | 데이터                                                |
| -------- | ---- | ----------------------- | ----------------------------------------------------- |
| active   | 가능 | 운영·종료 가능          | 정상 사용                                             |
| closed   | 불가 | 복구 또는 inactive 전환 | 채팅·참여 이력 유지, 복구 시 Playlist·Playback 초기화 |
| inactive | 불가 | 동작 불가               | 삭제에 준하는 종단 상태, 복구 불가                    |

### 4.2 역할

| 역할   | 설명                                                           |
| ------ | -------------------------------------------------------------- |
| Host   | Room 생성자이자 감상 흐름과 참여자 운영의 책임자               |
| Member | 초대 코드·링크로 참여해 공동 Playlist와 채팅에 참여하는 사용자 |
| Guest  | 현재 제품 기능에서는 사용하지 않으며, 확장 역할로만 둠         |

### 4.3 Member 상태

```ts
'online' | 'offline' | 'left' | 'kicked';
```

- `online`: 하나 이상의 Socket 연결이 유지되는 참여자
- `offline`: 연결은 끊겼지만 참여 이력은 유지되는 참여자
- `left`: 일반 퇴장 상태. 초대 코드·링크로 다시 입장 가능
- `kicked`: Host가 추방한 상태. Host가 해제하기 전까지 재입장 불가

### 4.4 권한

| 기능                            | Host | Member |  Guest |
| ------------------------------- | ---: | -----: | -----: |
| Room 생성·이름 수정             |    O |      X |      X |
| Room Close·복구·inactive 전환   |    O |      X |      X |
| 재생·일시정지·seek·곡 변경      |    O |      X |      X |
| 반복·셔플 설정                  |    O |      X |      X |
| Playlist 곡 추가                |    O |      O | 미사용 |
| 자신이 추가한 곡 삭제           |    O |      O | 미사용 |
| 모든 곡 삭제·순서 변경          |    O |      X | 미사용 |
| 개인 Playlist를 Room에 불러오기 |    O |      X | 미사용 |
| 채팅·이모지 입력                |    O |      O | 미사용 |
| Member 추방·추방 해제           |    O |      X |      X |

### 4.5 Close·복구 시 참여자 처리

- Close는 현재 감상 세션을 끝내고 모든 Socket Room 연결을 해제한다.
- 기존 Member의 참여 이력과 `kicked` 상태는 유지한다.
- 복구 뒤 기존 Member는 자동 입장하지 않으며, 기존 입장 권한으로 다시 참여한다.
- 복구 시 Playlist와 PlaybackState를 초기화한다.

## 5. 핵심 기능 요구사항

### 5.1 인증과 계정

- 사용자는 Google 계정으로 로그인·로그아웃할 수 있다.
- 인증된 사용자만 Private Room을 생성·입장·참여할 수 있다.
- 세션 만료 시 재인증 흐름을 제공한다.

### 5.2 Home과 Room 관리

- 사용자는 Home에서 Room을 생성할 수 있다.
- 초대 코드와 초대 링크로 active Room에 입장할 수 있다.
- 참여했던 active Room은 최근 Room 목록에서 다시 입장할 수 있다.
- Host는 `내 Room` 목록에서 자신이 만든 active, closed Room을 확인할 수 있다. inactive Room은 목록에서도 제외한다.
- Host는 active Room을 Close하고, closed Room을 복구하거나 inactive로 전환할 수 있다.

### 5.3 공동 Playlist와 음악 탐색

- 참여자는 YouTube 검색 또는 YouTube·YouTube Music 링크로 곡을 Room Playlist에 추가할 수 있다.
- Room Playlist는 동일 영상의 중복 추가를 허용하지 않는다.
- 참여자는 자신이 추가한 곡을 삭제할 수 있고, Host는 모든 곡을 삭제할 수 있다.
- Host는 Playlist 순서를 변경할 수 있다.
- 재생 또는 임베드가 불가능한 영상은 추가하지 않거나 재생 불가 상태로 표시한다.
- Playlist 변경은 모든 참여자에게 실시간 반영된다.

### 5.4 나만의 Playlist

- 사용자는 개인 Playlist를 생성·이름 변경·삭제·정렬할 수 있다.
- 사용자는 개인 Playlist에 YouTube 곡을 추가·삭제할 수 있다.
- Host는 자신의 개인 Playlist를 active Room Playlist 끝에 일회성으로 불러올 수 있다.
- 불러오기 시 중복·재생 불가 곡을 제외하고 결과를 안내한다.
- 공개 YouTube Playlist 가져오기는 향후 검토 항목으로 둔다.

### 5.5 Player

- Host는 재생, 일시정지, seek, 곡 변경을 제어할 수 있다.
- Host는 반복 없음·전체 반복·한 곡 반복과 셔플을 설정할 수 있다.
- 셔플 자동 재생은 한 사이클에서 같은 곡을 중복 선택하지 않는다.
- Host는 어떤 곡이든 직접 선택해 재생할 수 있다.
- Member는 현재 곡, 재생 상태, 반복·셔플 설정을 확인한다.

### 5.6 채팅과 참여자

- Room 참여자는 텍스트 채팅을 보내고 최근 채팅을 조회할 수 있다.
- 시스템 메시지로 입장·퇴장·Room 상태 변화를 안내한다.
- 채팅 입력창에서 Unicode 이모지를 선택·삽입할 수 있다.
- 서버는 기본 한국어 비속어 목록에 매칭되는 표현을 마스킹한 뒤 저장·전파한다.
- 참여자 목록과 온라인 상태를 실시간으로 표시한다.
- Host는 Member를 추방하고 추방 목록에서 해제할 수 있다.

### 5.7 PWA

- 사용자는 지원 브라우저에서 Syfity를 설치 가능한 웹앱으로 사용할 수 있다.
- 오프라인에서는 기본 안내 화면을 제공한다.
- 온라인 연결이 필요한 Room 감상·채팅·재생 기능은 오프라인에서 사용할 수 없음을 명확히 안내한다.

## 6. 실시간 동기화·오류·재연결 정책

### 6.1 동기화 원칙

- 서버가 곡, 재생 여부, 기준 재생 시각, 반복·셔플 설정, 셔플 큐를 권위 상태로 관리한다.
- Host의 재생 제어 요청은 서버 검증·저장 뒤 Room 전체에 전파한다.
- Member는 서버에서 전파된 상태를 기준으로 UI와 Player를 갱신한다.
- 서버 기준 시간으로 현재 재생 위치를 계산하고, 허용 오차를 넘으면 자동 보정한다.
- 수동 Sync 기능은 제공하지 않는다.
- 자동 다음 곡은 서버가 반복·셔플 정책에 따라 결정한다.

### 6.2 반복과 셔플

| 설정       | 곡 종료 시 동작                       |
| ---------- | ------------------------------------- |
| 반복 없음  | 다음 곡 재생, 마지막 곡이면 재생 중지 |
| 전체 반복  | 마지막 곡 뒤 첫 곡 재생               |
| 한 곡 반복 | 현재 곡을 처음부터 다시 재생          |

- 표시되는 Playlist 순서는 바꾸지 않는다.
- 셔플을 켜면 서버는 재생 가능한 곡의 내부 셔플 큐를 생성한다.
- 현재 곡은 이번 사이클에서 이미 재생한 곡으로 취급한다.
- 자동 다음 곡은 큐에서만 선택하며, 큐가 소진될 때까지 같은 곡을 자동으로 다시 선택하지 않는다.
- 전체 반복에서는 큐가 소진된 뒤 새 큐를 생성한다. 반복 없음에서는 재생을 중지한다. 한 곡 반복에서는 셔플보다 한 곡 반복이 우선한다.
- 곡 추가는 남은 셔플 큐의 무작위 위치에 넣고, 삭제·재생 불가 처리는 큐에서도 제거한다. Playlist 순서 변경은 현재 셔플 큐에 영향을 주지 않는다.
- Host가 특정 곡을 직접 선택하는 것은 항상 허용한다. 남은 큐의 곡이면 큐에서 꺼내 즉시 재생하고, 이미 이번 사이클에 들은 곡이면 즉시 재생하되 남은 큐는 유지한다.
- 셔플 상태에서도 이전 곡은 Playlist 순서가 아니라 실제 재생 이력을 기준으로 한다.

### 6.3 입장과 재연결

- Room 입장 또는 Socket 재연결 시 Room 정보, Playlist, PlaybackState, 반복·셔플 설정, 참여자 상태, 최근 채팅을 다시 동기화한다.
- 일반 Member 연결 해제는 5초 동안 재연결을 기다린다. 이 시간 안에 돌아오지 않으면 offline 상태로 표시한다.
- Host 연결 해제는 1분 동안 재연결을 기다린다. Host가 돌아오면 기존 Room 상태를 유지하고 참여자에게 재연결을 알린다.
- Host가 1분 안에 돌아오지 않으면 Room은 closed가 되고 참여자에게 종료를 알린다.

### 6.4 재생 실패와 오류 상태

- YouTube 영상이 재생 또는 임베드 불가 상태면 해당 곡을 `unavailable`로 표시한다.
- 재생 실패한 곡은 즉시 삭제하지 않는다.
- Host는 다음 곡을 선택하거나 재생을 중지할 수 있다.
- 새로운 곡 추가와 개인 Playlist 불러오기에서는 재생·임베드 가능 여부를 확인한다.

| 상황              | 사용자 경험                      |
| ----------------- | -------------------------------- |
| 인증 만료         | 재인증 안내                      |
| Room closed       | 종료 안내와 Home 이동            |
| Room inactive     | 더 이상 사용할 수 없는 Room 안내 |
| Member 추방       | 추방 안내와 Home 이동            |
| Socket 연결 끊김  | 재연결 진행 상태와 실패 안내     |
| 빈 Playlist       | 곡 추가 안내                     |
| YouTube 재생 실패 | 재생 불가 표시와 Host 제어 안내  |

동기화 허용 오차와 tick 주기 같은 값은 `03-realtime-sync-design.md`에서 관리한다.

## 7. 화면·사용자 흐름

PRD는 화면의 목적과 흐름만 정의한다. 반응형 레이아웃, 컴포넌트 규격, 색상은 UI/UX 및 디자인 시스템 문서에서 관리한다.

### 7.1 진입과 인증

```text
Landing → Google 로그인 → Home
```

- 비로그인 사용자는 Landing에서 서비스 소개와 로그인 진입점을 본다.
- 인증이 완료되면 Home으로 이동한다.
- 보호된 경로에 비인증 상태로 접근하면 로그인 흐름으로 이동한다.

### 7.2 Home

```text
Home
├─ Room 생성 → Room
├─ 초대 코드 입력 / 초대 링크 진입 → Room
├─ 최근 Room 재입장 → Room
├─ 내 Room 관리
│  ├─ active Room 입장
│  ├─ closed Room 복구
│  └─ closed Room inactive 전환
```

- 최근 Room은 사용자가 참여한 active Room의 재입장 흐름이다.
- 내 Room은 Host가 만든 Room의 상태 관리 흐름이다.
- 두 목록은 목적이 다르므로 화면에서 구분한다.

### 7.3 Room

```text
Room
├─ Player: 현재 곡, 재생 제어, 반복·셔플 상태
├─ Playlist: 검색·링크 추가, 순서 변경, 개인 Playlist 불러오기
├─ Chat: 메시지, 시스템 메시지, 이모지 입력
├─ Members: 온라인 상태, Host의 추방·추방 해제
└─ Host Room 관리: Close
```

- Host는 제어 가능한 기능을 보고, Member는 현재 상태와 결과를 실시간으로 확인한다.
- Room Close, Member 추방, inactive 전환처럼 되돌리기 어렵거나 영향이 큰 동작에는 확인 다이얼로그를 제공한다.
- Room이 closed되거나 추방되면 안내 뒤 Home으로 이동한다.

### 7.4 나만의 Playlist

개인 Playlist의 생성·관리와 Host의 Room 불러오기 기능은 제공한다. 화면 배치, 진입점, 선택·결과 표시 흐름은 UI 결정 뒤 정의한다.

### 7.5 PWA와 오프라인

- 지원 브라우저에는 설치 진입점을 제공한다.
- 오프라인 진입 시 전용 안내 화면을 제공한다.
- Room 감상 중 연결이 끊기면 오프라인 화면으로 강제 전환하지 않고, Room 안에서 재연결 상태를 안내한다.

## 8. 품질·운영 요구사항

### 8.1 테스트와 검증

- Backend는 단위·서비스·API 테스트를 제공한다.
- Frontend는 컴포넌트·훅·상태·API mocking 테스트를 제공한다.
- 핵심 사용자 흐름은 Docker 기반 로컬 DB 환경에서 Playwright E2E로 검증한다.
- E2E는 로컬에서 안정화한 뒤 CI에 추가한다.
- OAuth, 실제 YouTube 광고·재생처럼 자동화하기 어려운 외부 흐름은 테스트 대체 수단과 수동 검증 범위를 분리한다.

### 8.2 CI

- Backend 변경은 Backend lint, type-check, test를 실행한다.
- Frontend 변경은 Frontend lint, build, test를 실행한다.
- shared package·루트 설정·lockfile·CI 설정 변경은 전체 검증한다.
- 문서만 변경한 경우에는 변경 감지 job만 실행하고 검증 job은 skip한다.
- 분류하지 못한 변경은 안전하게 전체 검증한다.
- E2E가 준비되면 Frontend·Backend·shared·공통 설정 변경에서만 E2E job을 실행한다.

### 8.3 보안과 권한

- 인증된 사용자만 Private Room 기능에 접근할 수 있다.
- 역할 권한은 클라이언트 UI가 아니라 서버에서 검증한다.
- Host 전용 기능과 추방 상태는 REST·Socket 모든 진입점에서 동일하게 검증한다.
- 인증 정보와 사용자별 Room 데이터는 PWA 캐시로 저장하지 않는다.
- 사용자 입력은 형식·길이·권한을 검증하고, 오류를 사용자에게 안전한 메시지로 안내한다.

### 8.4 접근성과 반응형

- Landing, Home, Room, 오류·오프라인 화면은 모바일과 데스크톱에서 사용할 수 있어야 한다.
- 키보드로 핵심 조작과 다이얼로그를 사용할 수 있어야 한다.
- 실시간 채팅·참여자 갱신은 과도한 스크린리더 알림을 피한다.
- 로딩, 빈 상태, 오류 상태, 권한 없음 상태를 화면별로 제공한다.

### 8.5 운영 기본 요건

- 서비스 상태를 확인할 수 있는 health check를 제공한다.
- 서버 오류와 주요 상태 변화는 구조화 로그로 남긴다.
- 배포 뒤에는 health check, 인증, REST API, Socket 연결의 최소 동작을 확인한다.

## 9. 향후 검토 항목

이 장은 핵심 기능 요구사항에 넣지 않았지만, 제품 확장 시 별도 정책 설계가 필요한 항목을 정리한다. 우선순위와 구현 상태는 적지 않는다.

### 9.1 Public Room과 Guest

- 공개 Room 생성·목록·검색·정렬·카테고리
- 누구나 입장 가능한 공개 Room의 참여 제한과 노출 정책
- Guest의 입장·채팅·곡 추가 권한
- 로그인하지 않은 미리보기 사용자 지원 여부

Public Room, Guest, 모더레이션은 서로 의존하므로 하나의 정책군으로 설계한다.

### 9.2 모더레이션

- 사용자·Room·채팅·곡 신고
- 사용자 차단
- 채팅·곡 추가 제한
- 제재 이력과 운영 처리 흐름

기본 한국어 비속어 마스킹은 현재 채팅 기능에 포함한다. 이 항목은 신고·차단·제재처럼 운영 정책과 관리 흐름이 필요한 확장 모더레이션을 다룬다. Host의 Member 추방은 핵심 기능 요구사항에 포함하지만, 공개 Room의 신고·차단·운영 정책은 별도로 검토한다.

### 9.3 소셜과 추천

- 친구 추가와 온라인 상태
- 친구 기반 Room 초대
- 함께 들은 Room 기록
- 현재 Playlist·참여자 취향 기반 추천
- AI 기반 Playlist 추천

### 9.4 Playlist 확장

- 공개 YouTube Playlist URL을 개인 Playlist로 가져오기
- 비공개 YouTube Playlist 가져오기: Google OAuth 권한 확장과 YouTube 정책 검토 필요

### 9.5 채팅·알림 확장

- 메시지 이모지 반응
- 커스텀 이모지
- 실시간 floating reaction
- Push 알림과 알림 수신 설정

Host 위임·자동 Host 승계, 자체 음원 스트리밍·다운로드·광고 우회는 향후 검토 대상이 아니라 지원하지 않는 범위다.
