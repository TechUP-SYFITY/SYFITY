## 4. 전체 사용자 흐름

```text
Landing → Google 로그인 → Home

Home
├─ Room 생성 → 초대 코드·링크 공유 → Room
├─ 초대 코드·링크 입장 → Room
├─ 최근 Room 재입장 → Room
└─ 내 Room 관리
   ├─ active Room 입장
   └─ closed Room 복구 또는 inactive 전환

Room
├─ 곡 검색·링크 추가 → Playlist 실시간 갱신
├─ Host 재생 제어·반복·셔플 설정 → 서버 Socket 전파
├─ 채팅·Unicode 이모지 입력
├─ Host Member 추방·추방 해제
└─ Member 나가기 / Host Room 종료
```

inactive Room은 삭제에 준하는 상태로 Home과 Room 화면 어디에서도 표시하지 않는다.

## 5. Home과 Room 진입

### 5.1 Home (`/home`)

Home은 Room 생성·입장과 Host 운영의 허브다.

| 영역      | 구성                           | 동작                                              |
| --------- | ------------------------------ | ------------------------------------------------- |
| 헤더      | 로고, 프로필, 로그아웃         | 공통 탐색                                         |
| Room 생성 | 이름 입력, 생성 버튼           | 생성 뒤 초대 코드·링크를 복사하거나 Room으로 입장 |
| 초대 코드 | 코드 입력, 입장 버튼           | 성공 뒤 Room 경로로 이동                          |
| 최근 Room | active Room 카드               | 재입장                                            |
| 내 Room   | Host의 active·closed Room 카드 | active 입장, closed 복구·inactive 전환            |

- 최근 Room과 내 Room은 목적이 다르므로 시각적으로 구분한다.
- closed Room 카드에는 마지막 종료 시각과 `복구`, `inactive 전환`만 제공한다.
- inactive 전환이 성공한 Room은 목록에서 즉시 제거한다.
- 나만의 Playlist의 화면 배치와 진입점은 별도 UI 결정 전까지 정의하지 않는다.

**상태**

| 상태                | 처리                                                  |
| ------------------- | ----------------------------------------------------- |
| 최근 Room 없음      | “아직 참여한 Room이 없어요” 빈 상태                   |
| 내 Room 없음        | “만든 Room이 없어요” 빈 상태                          |
| 목록 로딩           | 영역별 스켈레톤 카드                                  |
| Room 복구 만료      | “더 이상 사용할 수 없는 Room이에요” 안내 후 목록 갱신 |
| Room 생성·입장 실패 | 인라인 오류 또는 Toast                                |

### 5.2 Room Join (`/room/join?code=ABC123`)

```text
초대 코드·링크 입력
  → POST /room-memberships
  → 성공: Room 경로 이동
  → Socket room:join → room:joined snapshot 수신
```

| 상태               | 처리                                                       |
| ------------------ | ---------------------------------------------------------- |
| 기본               | 초대 코드 입력과 입장 버튼                                 |
| 입장 중            | 스피너와 “방에 입장하는 중” 안내                           |
| 유효하지 않은 코드 | 코드 입력 하단 오류와 재시도                               |
| closed Room        | “이미 종료된 방이에요”와 Home 이동                         |
| inactive Room      | “더 이상 사용할 수 없는 방이에요”와 Home 이동              |
| 추방됨             | “Host가 다시 허용하기 전에는 입장할 수 없어요”와 Home 이동 |
| 비로그인           | 로그인 뒤 원래 초대 링크로 복귀                            |

## 6. Room 화면

### 6.1 레이아웃

```text
Desktop
┌──────────────────────────────────────────────────────────────┐
│ Header: Room 이름 · 초대 코드 복사 · 참여자 수 · 종료/나가기 │
├──────────┬───────────────────────────────┬───────────────────┤
│ Playlist │ Player: 영상·곡 정보·재생 설정 │ Members            │
│ 검색·링크 │ Host 제어 / Member 로컬 정지      ├───────────────────┤
│ 곡 목록   │                               │ Chat               │
├──────────┴───────────────────────────────┴───────────────────┤
│ Mini Player: 현재 곡 · 진행바 · 재생 상태                     │
└──────────────────────────────────────────────────────────────┘
```

- 모바일은 Player를 상단에 두고 Playlist·Chat·Members를 하단 탭으로 전환한다.
- 곡 추가는 모바일에서 모달 또는 바텀시트로 제공한다.
- Header의 Host 액션은 `Room 종료`, Member 액션은 `나가기`다. Host에게 일반 나가기 버튼을 별도로 노출하지 않는다.

### 6.2 Player와 반복·셔플

| 요소                           | Host        | Member                                                                 |
| ------------------------------ | ----------- | ---------------------------------------------------------------------- |
| 재생·일시정지·seek·곡 선택     | 제어 가능   | 재생·일시정지는 로컬 동기화 중지·재개, seek·곡 선택은 현재 상태만 표시 |
| 이전·다음 곡                   | 서버에 요청 | 상태만 표시                                                            |
| 반복 없음·전체 반복·한 곡 반복 | 설정 가능   | 선택된 모드 표시                                                       |
| 셔플                           | 설정 가능   | 켜짐·꺼짐 표시                                                         |

```text
Host 제어·설정 변경
  → Socket 요청
  → 서버 검증·재생 세션 갱신
  → Room 전체 이벤트 수신
  → 모든 Client가 Player·UI 갱신
```

- 셔플은 표시 Playlist 순서를 바꾸지 않는다.
- Host가 특정 곡을 직접 선택하는 것은 항상 가능하다.
- Member는 Room 전체 재생 상태를 직접 제어하지 않는다. Mini Player의 재생·일시정지 버튼으로 자신의 IFrame 동기화만 중지·재개할 수 있다. 정지 중에도 곡 정보·진행바는 서버 상태를 계속 표시하며, 재개 시 `playback:sync-request`로 최신 상태를 받아 다시 동기화한다.
- `playback:reset` 수신 시 “재생 상태가 초기화되었어요. Host가 다시 재생을 시작할 수 있어요.”를 안내하고 Player·설정 표시를 기본값으로 바꾼다.

### 6.3 Playlist

```text
검색 또는 YouTube·YouTube Music 링크 입력
  → REST로 곡 추가 요청
  → 성공 뒤 playlist:updated 수신
  → 전체 Playlist 갱신
```

- 참여자는 곡을 추가할 수 있다.
- Host는 전체 곡 삭제·순서 변경을 할 수 있고, Member는 자신이 추가한 곡만 삭제할 수 있다.
- 재생 불가 영상, 중복 영상, 잘못된 링크는 입력 영역에서 오류를 안내한다.
- Host의 나만의 Playlist 불러오기 기능은 제공하되, 버튼 위치·선택 화면·결과 표시 방식은 UI 결정 뒤 구체화한다.

### 6.4 Chat과 이모지

```text
메시지 입력 또는 이모지 버튼 선택
  → Unicode 이모지 삽입
  → chat:send
  → 임시 메시지 표시
  → ack의 최종 메시지(마스킹 결과 포함)로 교체
```

- 이모지 버튼은 표준 Unicode 이모지 선택기를 열고, 고른 문자를 현재 커서 위치에 삽입한다.
- 일반 텍스트와 동일하게 전송·저장·전파한다.
- 전송 중에는 optimistic UI를 사용한다. 성공 ack의 최종 메시지로 임시 항목을 교체하고, 실패하면 롤백·Toast를 표시한다. `chat:received`가 먼저 도착해도 id 기준으로 중복 표시하지 않는다.

### 6.5 Members와 추방 관리

- 참여자 목록은 아바타·이름·온라인 상태·Host 배지를 표시한다.
- Host는 Member 행의 관리 메뉴에서 추방 확인 모달을 열 수 있다. Host 자신에게는 메뉴를 제공하지 않는다.
- 추방 대상은 “Room에서 추방되었어요” 안내 뒤 Home으로 이동한다.
- 다른 Member에게는 일반 퇴장으로 표시한다.
- Host는 Members 영역의 추방 관리에서 추방 목록을 보고 해제할 수 있다. 해제된 사용자는 자동 입장하지 않는다.

### 6.6 종료·나가기·연결 상태

| 상황               | 사용자 경험                                      |
| ------------------ | ------------------------------------------------ |
| Member 나가기      | 즉시 Home 이동, 다른 참여자에게 일반 퇴장 표시   |
| Host Room 종료     | 확인 모달 → Room 종료 → 전체 종료 안내·Home 이동 |
| Host 명시적 나가기 | Room 종료와 같은 확인·종료 흐름                  |
| Host 연결 해제     | “1분 내 재접속을 기다리는 중” 상태 표시          |
| Host 복귀          | 연결 복구 안내, 기존 Room 유지                   |
| Host 1분 미복귀    | Room 종료 안내·Home 이동                         |
| `room:kicked`      | 추방 안내·Socket 해제·Home 이동                  |
| `room:closed`      | 종료 안내·Socket 해제·Home 이동                  |

Room이 closed가 되면 기존 Member는 자동으로 다시 입장하지 않는다. Host만 Home의 내 Room에서 복구할 수 있다.

## 7. PWA 흐름

### 7.1 설치와 업데이트

- 지원 브라우저에서는 설치 가능 상태일 때 설치 안내를 표시한다.
- iOS Safari에서는 브라우저의 “홈 화면에 추가” 절차를 안내한다.
- 새 배포본은 업데이트 가능 안내만 표시한다. active Room 중에는 자동 새로고침하지 않고 사용자가 적용을 선택한다.

### 7.2 오프라인

```text
오프라인 진입 → /offline 안내 화면
  → “Room 감상·채팅·재생은 인터넷 연결이 필요해요” 안내
  → 재연결 뒤 이전 경로 또는 Home으로 이동
```

PWA는 설치와 기본 안내만 제공한다. 오프라인 Room·Playlist·채팅·YouTube 재생은 제공하지 않는다.

## 8. 공통 UX

| 상황             | 패턴                            |
| ---------------- | ------------------------------- |
| 페이지·목록 로딩 | 스켈레톤 UI                     |
| 버튼 요청        | 버튼 내 스피너와 중복 클릭 방지 |
| 파괴적 작업      | 확인 모달                       |
| 입력 검증        | 필드 하단 인라인 오류           |
| 일시적 결과      | Toast                           |
| Socket 재연결    | 진행 상태와 실패 안내           |

### 빈 상태와 대표 오류

| 영역          | 빈 상태                      | 대표 오류                |
| ------------- | ---------------------------- | ------------------------ |
| 최근 Room     | 참여한 active Room 없음      | Room 입장 실패           |
| 내 Room       | 만든 active·closed Room 없음 | 복구 만료·종료 전환 실패 |
| Room Playlist | 곡 추가 안내                 | 재생 불가·연결 끊김      |
| Chat          | 첫 메시지 안내               | 전송 실패                |
| Search        | 검색 결과 없음               | YouTube 쿼터 초과        |

### 반응형·접근성

- Mobile(~~767px), Tablet(768~~1023px), Desktop(1024px~) 레이아웃을 제공한다.
- 모든 버튼은 키보드 포커스와 `aria-label`을 제공한다.
- 다크 모드의 본문 텍스트 대비는 WCAG AA(4.5:1 이상)를 목표로 한다.
- 채팅·참여자 상태 같은 실시간 영역은 과도한 스크린리더 알림을 막도록 `aria-live`를 제한적으로 사용한다.
