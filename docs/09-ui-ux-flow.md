## 2. 설계 원칙

Syfity의 화면은 "함께 듣고 있다"는 경험을 방해하지 않는 것을 최우선으로 한다.

| 원칙               | 설명                                                                           |
| ------------------ | ------------------------------------------------------------------------------ |
| 하나의 흐름        | 음악 감상, 플레이리스트, 채팅, 참여자 상태를 하나의 Room 화면 안에서 제공한다. |
| 최소 진입 마찰     | Google 로그인 후 Room 생성/입장까지 최소한의 단계로 도달한다.                  |
| 실시간 상태 우선   | 재생 상태·참여자 상태 등 실시간 정보를 항상 화면에서 즉시 확인할 수 있게 한다. |
| 다크 모드 기본     | 음악 감상 환경에 맞춰 어두운 배경을 기본 테마로 한다.                          |
| 반응형 대응        | 모든 화면은 데스크톱·모바일에서 자연스럽게 동작한다.                           |
| 명확한 상태 피드백 | 로딩, 빈 상태, 에러, 연결 끊김 등 모든 상태를 사용자에게 명시적으로 안내한다.  |

## 3. 화면 인벤토리

| 화면           | 경로             | 인증 | 설명                                          |
| -------------- | ---------------- | ---- | --------------------------------------------- |
| Landing        | `/`              | X    | 서비스 소개, Google 로그인 진입               |
| OAuth Callback | `/auth/callback` | X    | Google OAuth 콜백 처리, 로딩 화면             |
| Home           | `/home`          | O    | Room 생성, 초대 코드 입력, 최근 Room 목록     |
| Room Join      | `/room/join`     | O    | 초대 링크 진입점 (`?code=ABC123`)             |
| Room           | `/room/[roomId]` | O    | 음악 감상, Playlist, Chat, Presence 통합 화면 |

각 화면은 공통 레이아웃(헤더, 토스트 영역, 모달 포털) 위에 렌더링된다.

## 4. 전체 사용자 플로우

### 4.1 핵심 시나리오 (Happy Path)

```
Landing
  → Google 로그인
  → (OAuth Callback: 토큰 발급)
Home
  → Room 생성  ─────────────┐
  → 초대 코드 입력 ──────────┤
  → 최근 Room 재입장 ───────┤
                            ▼
Room 입장
  → YouTube 검색 / 링크로 곡 추가
  → Playlist에 곡 누적
  → Host 재생 시작
  → 서버 기준 재생 상태 동기화
  → 참여자 자동 합류(광고/버퍼링 후 현재 시점 보정)
  → 채팅으로 소통
  → 재생 / 일시정지 / Seek / 곡 변경 동기화
  → Room 재입장 또는 Host 종료
```

### 4.2 진입 분기

| 진입 경로             | 조건        | 도착 화면                    |
| --------------------- | ----------- | ---------------------------- |
| 서비스 첫 방문        | 미로그인    | Landing                      |
| 로그인 완료           | 쿠키 있음   | Home                         |
| 보호 페이지 직접 접근 | 미로그인    | Landing (`returnUrl` 유지)   |
| 초대 링크 클릭        | 로그인 상태 | Room Join → Room             |
| 초대 링크 클릭        | 미로그인    | Landing → 로그인 → Room Join |

### 4.3 인증 흐름

```
[Landing] 로그인 버튼 클릭
  → Google OAuth 동의 화면
  → [/auth/callback] 로딩 표시
      → JWT 발급, 쿠키 저장(access_token / refresh_token)
      → returnUrl 있으면 해당 경로, 없으면 /home 리다이렉트
```

- 라우트 보호: `proxy.ts`가 쿠키 존재 여부만 확인, 실제 JWT 검증은 보호 레이아웃(Server Component)에서 수행한다.
- Access Token 만료 시 `apiClient`가 자동으로 refresh 후 재시도한다.
- Refresh Token 만료 시 자동 로그아웃 후 Landing으로 이동한다.

## 5. 화면별 상세

### 5.1 Landing (`/`)

**목적**: 서비스 가치 전달 및 로그인 진입.

**구성 요소**

- 서비스 로고 및 슬로건 ("함께 듣는 실시간 음악 동기화")
- 핵심 가치 소개 섹션 (함께 듣기 / 공동 플레이리스트 / 실시간 채팅)
- Google 로그인 버튼 (Primary CTA)

**상태**

| 상태        | 처리                               |
| ----------- | ---------------------------------- |
| 기본        | 소개 콘텐츠 + 로그인 버튼 노출     |
| 로그인 진행 | 버튼 로딩 스피너, OAuth 리다이렉트 |
| 이미 로그인 | Home으로 리다이렉트                |

### 5.2 OAuth Callback (`/auth/callback`)

**목적**: OAuth 콜백 처리 중 사용자에게 진행 상태 안내.

- 중앙 로딩 인디케이터와 "로그인 처리 중" 문구 노출
- 성공 시 `returnUrl` 또는 `/home`으로 리다이렉트
- 실패 시 Landing으로 이동 + 에러 토스트

### 5.3 Home (`/home`)

**목적**: Room 생성·입장의 허브.

**구성 요소**

- 헤더: 로고, 사용자 프로필(아바타/이름), 로그아웃
- Room 생성 영역: Room 이름 입력 + 생성 버튼
- 초대 코드 입력 영역: 코드 입력 + 입장 버튼
- 최근 Room 목록: 카드 리스트 (Room 이름, 상태 배지, 마지막 활동 시각, 재입장 버튼)

**주요 인터랙션**

```
Room 생성 클릭 → [방 만들기 모달] 방 이름 입력 → POST /rooms
  → [방 생성 완료 모달] 초대 코드 + 초대 링크 표시(복사 가능)
  → "방으로 입장하기" → 생성된 roomId로 이동
초대 코드 입장 → POST /rooms/join → Room으로 이동
최근 Room 카드 클릭 → 해당 roomId로 이동
```

**방 만들기 모달 (Create Room)**

- 입력 폼: 방 이름(필수, 예 "Chill Night") + 취소 / 만들기 버튼
- 생성 완료: 성공 아이콘, "방이 만들어졌어요!" + 방 이름 확인, 초대 코드(예 `3F9A2C`)·초대 링크(`https://syfity.app/room/join?code=3F9A2C`) 각각 복사 버튼, "방으로 입장하기" CTA

**상태**

| 상태           | 처리                                    |
| -------------- | --------------------------------------- |
| 최근 Room 있음 | 카드 리스트 렌더링                      |
| 최근 Room 없음 | 빈 상태 UI("아직 참여한 Room이 없어요") |
| 로딩           | 스켈레톤 카드                           |
| 생성/입장 실패 | 인라인 에러 메시지 또는 토스트          |

### 5.4 Room Join (`/room/join?code=ABC123`)

**목적**: 초대 코드/링크로 진입한 사용자를 Room으로 연결. "초대 코드로 입장" 카드(아이콘 배지 + 제목 + 설명 + 코드 입력 + 취소/입장하기)를 중심으로, 진입 상황에 따라 상태별 화면을 제공한다.

```
링크/코드 진입
  → code 파라미터로 POST /rooms/join
  → 성공: Room으로 리다이렉트
  → 실패: 상황별 상태 화면(아래) 표시
```

**상태별 화면 (Figma `3. Room 진입`)**

| 상태        | 화면                                                                         |
| ----------- | ---------------------------------------------------------------------------- |
| 기본        | 초대 코드 입력(플레이스홀더 `예: 3F9A2C`), 카운터 `0 / 6`                    |
| 링크 입력   | 붙여넣은 링크에서 코드 자동 인식, 카운터 `6 / 6`                             |
| 입장 로딩   | 스피너 + "방에 입장하는 중... / 잠시만 기다려주세요"                         |
| 비로그인    | "입장하려면 로그인이 필요해요" + Google 계정 로그인 버튼 + 홈으로            |
| 잘못된 코드 | 입력 하단 에러 "유효하지 않은 초대 코드예요. 다시 확인해주세요." + 다시 시도 |
| 종료된 방   | "이미 종료된 방이에요" (호스트가 방을 닫음) + 홈으로 돌아가기                |
| 비활성 방   | "입장할 수 없는 방이에요" (오랜 미활동으로 자동 비활성) + 홈으로 돌아가기    |

- 초대 코드는 6자리(예 `3F9A2C`), 입력 카운터로 길이를 안내한다.
- 미로그인 진입 시 로그인 유도 후 `returnUrl`로 복귀한다.

### 5.5 Room (`/room/[roomId]`)

Syfity의 핵심 화면. 여러 feature(player, playlist, chat, presence, search)가 하나의 화면에 통합된다.

**레이아웃 (데스크톱)** — 고정 폭 사이드 패널 + 가변 중앙, 하단 Mini Player 고정

```
┌──────────────────────────────────────────────────────────────┐
│ Room Header (h-64)  Room 이름 · 초대코드 복사 · 참여자수 · 나가기 │
├──────────┬───────────────────────────────┬───────────────────┤
│ Playlist │        Center (flex-1)        │ Members (w-280)   │
│ (w-320)  │        Player (현재 곡)       │  참여자 목록/상태  │
│  곡 목록 │        - 영상 / 곡정보        ├───────────────────┤
│  곡 추가 │        - (Host만 컨트롤)      │ Chat (w-320)      │
│          │                               │  메시지 / 입력창   │
├──────────┴───────────────────────────────┴───────────────────┤
│ Mini Player (h-80)  현재 곡 · 진행바 · 재생 컨트롤            │
└──────────────────────────────────────────────────────────────┘
```

규격: Header `h-16`(64px), Mini Player `h-20`(80px), Playlist `w-320`, Members `w-280`(min 200), Chat `w-320`, Center `flex-1 min-w-200`, 카드 간격 `gap-6`(24px). 상세는 `10-design-system.md` §5.5 참조.

**레이아웃 (모바일)**

- Player를 상단 고정, 하단은 탭(Playlist / Chat / 참여자)으로 전환
- Mini Player는 하단 고정 유지
- 곡 추가는 모달 또는 바텀시트로 제공

**역할별 UI 차이**

| 요소          | Host                   | Member                        |
| ------------- | ---------------------- | ----------------------------- |
| 재생 컨트롤   | 재생/정지/Seek/곡 변경 | 조회만 (동기화된 상태 표시)   |
| Playlist 순서 | 변경 가능              | 조회만                        |
| 곡 추가       | 가능                   | 가능                          |
| 곡 삭제       | 가능                   | 정책에 따름 (본인 추가 곡 등) |
| Room 종료     | 가능                   | 불가                          |

## 6. Room 내 세부 인터랙션 흐름

### 6.1 곡 추가 (검색)

```
검색창에 키워드 입력
  → GET /search (YouTube Data API)
  → 검색 결과 리스트 표시(썸네일/제목/채널/길이)
  → 곡 선택 → Playlist에 추가(Socket: playlist:add)
  → 참여자 전원 Playlist 실시간 갱신
```

### 6.2 곡 추가 (링크)

```
YouTube / YouTube Music 공유 링크 붙여넣기
  → videoId 파싱 및 유효성 검증
  → 유효: Playlist 추가
  → 무효(PLAYLIST_INVALID_URL): 입력창 하단 에러 메시지
```

### 6.3 재생 동기화

```
Host가 재생 시작 (Socket: playback:play)
  → 서버가 serverStartedAt / baseCurrentTime / isPlaying 브로드캐스트
  → 각 클라이언트 YouTube IFrame Player가 해당 시점으로 seek 후 재생
  → 10초 주기 playback:tick으로 오차 자동 보정
  → 신규 입장자는 광고/버퍼링 종료 후 현재 Room 시점으로 자동 합류
```

- 오차 목표: 참여자 간 재생 위치 2초 이내
- Member에게는 컨트롤 대신 "Host가 재생 중" 상태 표시

### 6.4 채팅

```
메시지 입력 후 전송
  → Optimistic UI로 즉시 표시
  → Socket: chat:message 전송/수신
  → 실패 시 롤백 + 재전송 안내 토스트
시스템 메시지: 입장/퇴장/곡 변경 등은 별도 스타일로 구분
```

### 6.5 참여자 상태 (Presence)

- 참여자 목록에 아바타·이름·온라인 상태 표시
- 입장/퇴장 시 목록 실시간 갱신 및 채팅 시스템 메시지 노출
- Host 표시 배지 별도 노출

### 6.6 Room 종료 / 나가기

```
Member 나가기 → room:leave → Home으로 이동
Host 종료 → 확인 모달 → POST /rooms/{id}/close
  → 참여자 전원에게 종료 안내 → Home으로 이동
Host 비정상 이탈 → 정책에 따라 Room 상태 관리(재입장 대기/closed)
```

## 7. 공통 UX 패턴

### 7.1 로딩

| 상황             | 패턴                      |
| ---------------- | ------------------------- |
| 페이지 초기 로딩 | 스켈레톤 UI               |
| 목록 로딩        | 스켈레톤 카드/리스트      |
| 버튼 액션        | 버튼 내 스피너 + 비활성화 |
| 콜백 처리        | 전체 화면 로딩 인디케이터 |

### 7.2 피드백

- 일시적 알림: Toast (성공/실패/정보)
- 파괴적 액션(Room 종료 등): 확인 모달
- 폼 검증 오류: 입력 필드 하단 인라인 메시지

### 7.3 빈 상태 / 에러 상태

세부 정의는 `11-error-empty-state.md`에서 관리하며, 본 문서는 화면별 진입점만 정의한다.

| 화면 | 빈 상태               | 대표 에러                               |
| ---- | --------------------- | --------------------------------------- |
| Home | 최근 Room 없음        | Room 생성/입장 실패                     |
| Room | 빈 Playlist / 빈 채팅 | 방 입장 실패, 영상 재생 실패, 연결 끊김 |
| 검색 | 결과 없음             | 검색 실패, YouTube 쿼터 초과            |

### 7.4 반응형 브레이크포인트

| 구분    | 기준           | 주요 변화                                    |
| ------- | -------------- | -------------------------------------------- |
| Mobile  | ~ 767px        | Player 상단 고정 + 탭 전환 레이아웃          |
| Tablet  | 768px ~ 1023px | 2열 축소 레이아웃                            |
| Desktop | 1024px ~       | Player + 사이드(Playlist/Chat/Presence) 병렬 |

## 8. 접근성

- 모든 인터랙티브 요소는 키보드 포커스 및 명확한 포커스 링을 제공한다.
- 아이콘 단독 버튼에는 `aria-label`을 제공한다.
- 다크 모드 기준 텍스트 대비는 WCAG AA(본문 4.5:1 이상)를 목표로 한다.
- 실시간 갱신 영역(채팅, 참여자)은 스크린리더 과다 알림을 피하도록 적절한 `aria-live` 정책을 적용한다.
